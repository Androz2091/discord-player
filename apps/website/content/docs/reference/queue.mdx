title: GuildQueue and playback node

`GuildQueue` owns application-level playback scheduling. `GuildQueuePlayerNode` provides controls over the underlying Remedia session.

## Create, connect, play

```ts
const queue = await player.createQueue(guildId, {
  maxSize: 100,
  maxHistorySize: 50,
  metadata: { textChannelId },
});

await queue.connect({ channelId, volume: 75, connectTimeoutMs: 120_000 });
await queue.play(track);
```

## Queue methods

| Method | Purpose |
| --- | --- |
| `addTrack(trackOrArrayOrPlaylist)` | Append future Tracks |
| `addTracks(tracks)` | Append multiple Tracks |
| `prepend(...)`, `append(...)`, `insertTrack(...)` | Reorder upcoming Tracks |
| `removeTrack(...)`, `moveTrack(...)`, `swapTracks(...)` | Modify future ordering |
| `play(resource, options?)` | Queue-managed playback |
| `playNext()` | Start next upcoming Track when idle |
| `skip(reason?)`, `skipTo(...)`, `jump(...)` | Managed navigation |
| `stop()` | Stop managed playback, retain upcoming Tracks |
| `connect(options)` | Connect/move channel through Remedia |
| `setSelfDeaf(bool)`, `setSelfMute(bool)` | Update voice flags |
| `destroy()`, `delete()` | Release queue resources |
| `clear()` | Clear upcoming Tracks and history |

## Connection deadline

`connectTimeoutMs` is optional and applies to a new voice join or an explicit reconnect. Remedia defaults to 100 seconds. It does not change the independent 80-second `voice.connect` RPC deadline or a channel move's internal timeout. `player.play(channel, resource, { connectTimeoutMs })` forwards the same option. See [voice recovery](/docs/remedia/voice-recovery).

## Queue state

| Property | Value |
| --- | --- |
| `guildId` | Owning guild ID |
| `currentTrack` | Active or paused Track or `null` |
| `tracks` | Upcoming Track collection |
| `size` | Upcoming Track count, excludes current |
| `history` | Previous-track manager |
| `node` | GuildQueuePlayerNode |
| `metadata` | App-defined metadata |
| `repeatMode` | OFF, TRACK, QUEUE, AUTOPLAY |
| `isShuffling` | Shuffle state |
| `isPlaying()` | Managed active status (includes paused) |

## Node/session API

```ts
await queue.node.pause();
await queue.node.resume();
await queue.node.seek(15_000);
await queue.node.setVolume(80);
await queue.node.filters.set(['8d', 'nightcore']);

const session = queue.node.getSession();
console.log(session.nodeId);
```

| Node method/property | Meaning |
| --- | --- |
| `play(source, options?)` | **Raw** Remedia playback, not managed Track scheduling |
| `playRaw(source, options?)` | Alias to raw playback |
| `stopSession()` | Stop raw session audio |
| `pause()`, `resume()`, `setPaused(bool)` | Raw playback state |
| `seek(ms)`, `setVolume(percent)` | Raw timing and gain controls |
| `playbackTime`, `totalDuration` | Millisecond timeline |
| `getTimestamp()`, `createProgressBar()` | Display helpers |
| `isIdle()`, `isPlaying()`, `isPaused()` | Raw session status |
| `filters` | Named/raw FFmpeg filtergraph API |

The managed queue serializes conflicting transitions and correlates playback generations. Prefer its methods for user commands.
