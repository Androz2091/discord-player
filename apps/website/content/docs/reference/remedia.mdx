---
title: Remedia configuration
description: Configure embedded/remote engine nodes, inspect status, and understand session boundaries.
---

The Player receives a Remedia node pool through `DiscordPlayerOptions.nodes`. This is separate from `player.nodes`, which remains an alias for the guild queue manager.

## Embedded node

```ts
nodes: [{ type: 'embedded', id: 'local', capacity: 8 }]
```

An embedded node uses `@remedia/node` directly inside the application and needs FFmpeg 7 shared libraries on that host.

## Remote node

```ts
nodes: [{
  type: 'remote',
  id: 'audio-1',
  url: 'remedias://audio.example.com',
  auth: { username: 'bot', password: process.env.REMEDIA_PASSWORD! },
}]
```

A remote node runs the same Rust engine in `remedia-server`. The bot host does not need FFmpeg if it uses only remote nodes. Use TLS and server-side source access controls.

## Player integration

```ts
const player = new Player({
  nodes,
  send: (guildId, packet) => sendToShard(guildId, packet),
});
await player.initialize(botUserId);

const remedia = player.getRemedia();
console.log(player.nodeSnapshots);
```

The bot forwards raw Gateway dispatches with `player.receive(packet)`. `botUserId` scopes sessions and identifies the account for Discord voice; a single server can serve independent bot clients.

## Placement and media limits

A guild assignment stays sticky to its selected healthy node. Queue-specific `selectNode` options can influence placement. Embedded mode can consume local binary Readables; remote mode accepts only server-accessible URLs or file paths from discord-player's source resolution.

For details on low-level session migration, event generations, reconnection, and protocol, refer to the [Remedia client reference](https://github.com/twlite/remedia/blob/main/apps/docs/content/docs/client/overview.mdx).
