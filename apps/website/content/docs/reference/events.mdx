There are two event emitters:

- `player.on()` for Player-level `debug`, `error`, and voice-state diagnostics.
- `player.events.on()` for queue-scoped lifecycle and playback events. The first argument is the owning queue.

## Queue events

| Name                            | Arguments after queue                     |
| ------------------------------- | ----------------------------------------- |
| `queueCreate`                   | none                                      |
| `queueDelete`                   | none                                      |
| `connection`                    | none                                      |
| `connectionDestroyed`           | none                                      |
| `disconnect`                    | none                                      |
| `audioTrackAdd`                 | `track`                                   |
| `audioTracksAdd`                | `tracks`                                  |
| `audioTrackRemove`              | `track`                                   |
| `audioTracksRemove`             | `tracks`                                  |
| `playerStart`                   | `track, rawEvent?`                        |
| `playerFinish`                  | `track, rawEvent?`                        |
| `playerSkip`                    | `track, reason, description, rawEvent?`   |
| `playerStop`                    | `trackOrNull, rawEvent?`                  |
| `playerError`                   | `error, track, rawEvent?`                 |
| `playerPause`                   | `rawEvent`                                |
| `playerResume`                  | `rawEvent`                                |
| `playerSeek`                    | `rawEvent`                                |
| `voiceConnectionStateChange`    | `previousState, state, rawEvent`          |
| `volumeChange`                  | `oldPercentage, newPercentage, rawEvent?` |
| `emptyQueue`, `emptyChannel`    | none                                      |
| `willPlayTrack`, `willAutoPlay` | `track`                                   |
| `error`                         | `error`                                   |

The exported `GuildQueueEvents` constant contains the canonical string identifiers. Some historic event names are retained for type compatibility, but that does not mean every old DSP pipeline is recreated.

## Example

```ts
player.events.on('playerSkip', (queue, track, reason, description) => {
  console.log(queue.guildId, track.title, reason, description);
});
```

Treat terminal events separately. A natural finish advances differently from a stop, skip, or failure, and should not be conflated in analytics or music-command responses.

## Native event forwarding

All queue events backed by Remedia append the original typed event as the final
argument. Application-owned operations have no fabricated native event. Playback
compatibility events retain the queue-owned Track; raw playback without a managed
Track is visible through native observation instead.

```ts
player.events.on('volumeChange', (queue, oldVolume, newVolume, rawEvent) => {
  console.log(queue.guildId, oldVolume, newVolume, rawEvent?.generation);
});

player.events.on('stageFailed', (queue, track, error, rawEvent) => {
  console.log(queue.guildId, track?.title, error.message, rawEvent?.entryId);
});

player.events.on('sessionEvent', (queue, name, rawEvent) => {
  // Includes notifications rejected by queue generation correlation.
  console.log(queue.guildId, name, rawEvent.sessionId);
});
```

| Queue event                                       | Arguments after queue            | Native payload type                              |
| ------------------------------------------------- | -------------------------------- | ------------------------------------------------ |
| `willPrepareNextTrack`                            | `track, rawEvent`                | `DiscordSessionEvents['prepareRequested'][0]`    |
| `stageReady`                                      | `trackOrNull, rawEvent`          | `DiscordSessionEvents['stageReady'][0]`          |
| `stageFailed`                                     | `trackOrNull, error, rawEvent?`  | `DiscordSessionEvents['stageFailed'][0]`         |
| `stageInvalidated`                                | `trackOrNull, rawEvent`          | `DiscordSessionEvents['stageInvalidated'][0]`    |
| `transitionCancelled`                             | `trackOrNull, rawEvent`          | `DiscordSessionEvents['transitionCancelled'][0]` |
| `sessionDisposed`                                 | `rawEvent`                       | `DiscordSessionEvents['sessionDisposed'][0]`     |
| `audioFiltersUpdate`                              | `oldGraph, newGraph, rawEvent`   | `DiscordSessionEvents['filterChanged'][0]`       |
| `voiceConnectionStateChange`                      | `previousState, state, rawEvent` | `DiscordSessionEvents['voiceStateChanged'][0]`   |
| `error` from voice failure                        | `error, rawEvent`                | `DiscordSessionEvents['voiceFailed'][0]`         |
| `sessionResumed`, `sessionLost`                   | `rawEvent`                       | Corresponding `RemediaClientEvents` payload      |
| `guildAssigned`, `guildReleased`, `guildMigrated` | `rawEvent`                       | Corresponding `RemediaClientEvents` payload      |

Preparation is observational and can occur again after cancellation or retry. It
runs before source resolution. Staging never emits `playerStart`; native promotion
starts the incoming Track. A stage failure does not imply the current Track failed.
A null staging Track means its occurrence could not be correlated reliably.

`sessionEvent(queue, name, rawEvent)` observes all 17 installed session notification
kinds, including stale generations, before compatibility processing. It does not
change queue state. After session disposal, owned subscriptions are removed;
caller-owned session listeners are retained.

All native `RemediaClientEvents` are also available on `player.on()` with their
unchanged native argument tuples, including `nodeConnected`, `nodeDisconnected`,
`sessionResumed`, `sessionLost`, `nodeEvent`, `eventsLost`, `guildAssigned`,
`guildReleased`, and `guildMigrated`. Guild notifications project onto existing
queues only. No queue is created to deliver a notification. Global native playback
observations and queue compatibility events represent different scopes.

Volume gain is converted to percentages (including native gains above 1). Generic
filter changes expose raw previous/current graphs, and do not fabricate equalizer,
reverb, compressor, or other legacy DSP events. Native notifications also update
queue configuration defaults. Connected convenience methods rely on native volume
notifications rather than emitting the same change twice.

`voiceConnectionStateChange` describes Remedia transport recovery. It is distinct
from Discord Gateway member `VOICE_STATE_UPDATE`; gateway membership policy
restoration is still pending. The previously declared queue `voiceStateUpdate`
transport mapping is no longer emitted.
