## Why operations instead of a dedicated extractor pipeline?

One source may match a URL, another may resolve related metadata, and a third may transform an encoded stream. Those are distinct tasks with different ownership and failure behavior. The registry provides named, typed operations so plugins can register only what they implement.

```text
search.query.match → search.query.resolve → Track
                                        ↓
                                 track.stream
                                        ↓
                                 stream.transform
                                        ↓
                              Remedia MediaSource
```

The compatibility adapter translates supported `BaseExtractor` methods into these **same** operations. It does not run a second hidden dispatcher.

<Callout title="What is implemented today?">
Source plugins are implemented and run in the application process. The `runtime` plugin kind, remote plugin execution, and automatic distribution are not implemented in this version. Do not write plugins that depend on those features.
</Callout>
