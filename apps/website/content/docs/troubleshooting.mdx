---
title: Troubleshooting
description: Diagnose installation, source selection, voice transport, and playback problems systematically.
---

Start by locating the layer that failed. A missing source plugin and a failed native decoder are different problems.

## Installation and native runtime

**Symptom:** `ERR_DLOPEN_FAILED`, missing `.node` addon, `avcodec`/FFmpeg shared library errors, or missing Windows DLLs.

**Check:** Node.js version, CPU architecture, platform optional dependencies, and the five required FFmpeg 7 shared library ABI majors. Run the [native loading checklist and smoke test](/docs/installation/ffmpeg#troubleshooting). Embedded hosts need the libraries locally; remote-only bot hosts do not.

## No matching tracks

**Symptom:** `player.search(query)` returns no Tracks or a string query never starts playback.

**Check:** `plugins` registrations, the `search.query.match` handler, query protocol, `blockExtractors`, explicit `pluginId`, and `search.query.resolve`. A Track's URL alone does not automatically register a decoder source.

## Source fails at playback

**Symptom:** Metadata resolves, but `playerError` fires when the Track is played.

**Check:** `track.stream` is registered and returns an accessible media source. For remote nodes, the URL/file must be reachable from the audio server, not just the bot. Validate credentials/redirects and codec support. Inspect the associated native error.

## Voice never becomes connected

**Check:** Guild voice permissions, botUserId, the correct shard in `send`, and forwarding of `VOICE_STATE_UPDATE` and `VOICE_SERVER_UPDATE`. `player.receive()` should run on raw Gateway dispatches, not just a high-level voice-state callback.

## Playback stops, skips, or repeats unexpectedly

**Check:** Use `queue.play()` for managed Tracks, not `queue.node.play()`. Verify repeat mode and that application event listeners are not manually advancing a queue on `playerFinish`. [Queue lifecycle](/docs/architecture/lifecycle) explains the ownership boundary.

## Legacy extractor breaks

**Check:** Is the registered value a `BaseExtractor` subclass constructor? Does its `stream()` return an encoded media source instead of relying on retired voice pipe objects? If the source uses private `raw.engine`, migrate it to a public URL or a portable `sourceReference`.
