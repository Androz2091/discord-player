discord-player does not open a Discord Gateway connection itself. Your bot library owns the connection; Remedia uses it to obtain Discord voice credentials.

## The send/receive contract

```ts
const player = new Player({
  nodes: [{ id: 'local', type: 'embedded' }],

  send(guildId, packet) {
    return gateway.sendToGuildShard(guildId, packet);
  },
});

gateway.onDispatch((packet) => player.receive(packet));
await player.initialize(botUserId);
```

`gateway.sendToGuildShard` and `gateway.onDispatch` are application integration points, **not** discord-player exports. For an executable discord.js example, see [create a player](/docs/getting-started/create-player).

Pass every raw dispatch to `player.receive()`. Remedia receives all packets, including `READY`, and ignores those it does not need; filtering them first can break Gateway-session ordering. Discord Player separately tracks `VOICE_STATE_UPDATE` for queue voice policies. `send` must reject when a guild cannot be routed to a shard; do not silently swallow missing guilds. Each bot account must use its own authenticated user identity, even if multiple bots share a guild or voice channel.

## Connect or move channels

```ts
const queue = await player.createQueue(guildId);

await queue.connect({
  channelId: firstVoiceChannelId,
  selfDeaf: true,
  selfMute: false,
  volume: 70,
  connectTimeoutMs: 120_000, // Optional initial-join timeout
});

await queue.connect({ channelId: nextVoiceChannelId });
```

The second call reuses the queue/session and requests a voice channel move. It does not intentionally clear history or create a new managed queue.

## Update voice flags

```ts
await queue.setSelfDeaf(false);
await queue.setSelfMute(true);
```

These settings update both the connected session and the defaults for subsequent sessions. Queue volume is percentage-based; session-level linear volume is a Remedia detail.

## Handle voice recovery

```ts
player.events.on('voiceConnectionStateChange', (queue, previousState, state, rawEvent) => {
  if (state === 'reconnecting') {
    console.log('Recovering voice', queue.guildId);
  }
});
```

Remedia retries transient initial remote join failures with fresh Gateway credentials. The default initial join deadline is 100 seconds. Ordinary remote requests retain their separate 15-second timeout.

Avoid treating a brief voice reconnect as a completed Track. The queue and Remedia have separate state machines. A channel move is not the same thing as moving a decoder to another Remedia node.

## Authoritative channel occupancy

Bot joins, moves, disconnects, server mute and stage suppression are recognized
from the bot identity supplied to `initialize()`, without a membership resolver.
Raw Gateway packets still reach Remedia. Queue `voiceStateUpdate` listeners receive
`(queue, previousOrNull, current, rawPacket)` with normalized IDs and available mute
flags. Unknown previous state stays null; listeners never disable default handling.
Remedia transport notifications remain separate `voiceConnectionStateChange` events.

For empty-channel behavior, configure `resolveVoiceChannelUsers(guildId, channelId)`
on the Player. Return non-bot member IDs, `[]` for confirmed empty, or null for an
unavailable snapshot. Resolver failures emit queue `error` and leave occupancy
unknown. The core does not infer a complete channel from partial Gateway history.

Requests are coalesced after connection and relevant Gateway changes. Channel,
session and revision checks reject stale responses. There is one occupancy Set per
queue, and no mandatory Discord library dependency. An integration adapter may
supply authoritative IDs from its channel cache when complete.

## Queue leave and pause policies

```ts
const queue = await player.createQueue(guildId, {
  leaveOnEmpty: true,
  leaveOnEmptyCooldown: 30_000,
  pauseOnEmpty: true,
  leaveOnEnd: true,
  leaveOnEndCooldown: 60_000,
  leaveOnStop: true,
  leaveOnStopCooldown: 10_000,
});
```

Policies are opt-in. `leaveOnEmpty` and `pauseOnEmpty` act only on confirmed occupancy.
`emptyChannel` and `channelPopulate` report confirmed transitions. An empty cooldown
revalidates occupancy before deletion. Null snapshots never mean empty.

`leaveOnEnd` follows natural exhaustion (including related-track autoplay declining);
`leaveOnStop` follows managed stop. Neither needs an occupancy resolver. New playback,
applicable enqueues, moves, replacement and destruction invalidate obsolete timers.
Repeat and crossfade continuation do not count as exhaustion; skipping alone does
not trigger the natural-end leave policy.

Only policy-owned pauses are automatically resumed. Calling `queue.node.pause()`
explicitly retains the user pause after repopulation. Server mute/suppression also
pause playback; release resumes only a policy-owned pause. Requesting stage speaking
permission remains the integration's responsibility because Remedia exposes no
corresponding request-to-speak API.
