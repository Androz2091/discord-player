A Remedia node hosts multiple independent player sessions. A guild queue uses one selected session; future audio tracks on that queue reuse it until the session changes.

## Inspect nodes

```ts
const remedia = player.getRemedia();

console.log(player.nodeSnapshots);
console.log(remedia.nodes);
```

`player.nodes` is the legacy queue-manager alias. The actual audio-node state is on `player.remedia` and `player.nodeSnapshots`.

## Select a node for a queue

```ts
const queue = await player.createQueue(guildId, {
  selectNode(nodes) {
    return nodes[0]!.id;
  },
});
```

Without `selectNode`, Remedia places a new guild on the healthy node with the lowest allocation relative to its reported capacity, breaking ties by node ID. Nodes that are degraded, full or disconnected, or that lack a required plugin host, are excluded.

A queue's `selectNode` callback replaces that choice. It receives only those eligible nodes, runs once when the guild's first session is created, and its returned ID is pinned for the session. It is skipped when `nodeId` is passed explicitly or the guild already has a node. Remedia still rejects an unknown or unavailable ID. The example picks the first offered candidate only for clarity, not as a production placement algorithm.

Automatic crossfade is requested only when the chosen node supports it. Without a selector or pinned node, it is requested only if every eligible node supports crossfade; otherwise the queue plays without it and emits a `debug` message. Pin a node with `nodeId` or provide `selectNode` for a mixed pool.

## Practical trade-offs

| Concern                 | Embedded                | Remote                        |
| ----------------------- | ----------------------- | ----------------------------- |
| Process model           | Audio in bot process    | Separate Rust service         |
| Native FFmpeg libraries | Bot machine             | Audio server                  |
| Transport control       | Direct native binding   | Authenticated WebSocket RPC   |
| Local Node Readables    | Available               | Not transferred               |
| Failure isolation       | Shared bot process      | Independent audio service     |
| Scaling                 | Scale whole bot process | Add audio nodes independently |

For remote servers, run `remedia-server --list` on the server host to see locally discovered instances, active players, current connections, resident memory when available, and health. `remedia-server doctor --config ./remedia.config.json --env-file .env` checks the loaded FFmpeg 9 libraries and server configuration. These are administrative commands, not methods on `player.getRemedia()`.

For metrics and debugging, use Remedia's [observability documentation](https://github.com/twlite/remedia/tree/main/apps/docs/content/docs/observability). Limit sensitive media locations and authentication details in logs.
