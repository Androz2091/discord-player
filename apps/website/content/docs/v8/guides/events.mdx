---
title: Events
description: React to playback, queue changes, and errors.
---

Listen to `player.events` for events related to a guild queue. The first callback argument is always the queue.

```ts
player.events.on('playerStart', (queue, track) => {
  console.log('Playing', track.title);
});

player.events.on('playerFinish', (queue, track) => {
  console.log('Finished', track.title);
});

player.events.on('playerError', (queue, error, track) => {
  console.error('Cannot play', track.title, error);
});
```

## Common events

| Event                 | When it happens             |
| --------------------- | --------------------------- |
| `playerStart`         | A track starts              |
| `playerFinish`        | A track finishes naturally  |
| `playerSkip`          | A track is skipped          |
| `playerStop`          | Playback stops              |
| `playerError`         | A track fails               |
| `audioTrackAdd`       | A track is added            |
| `emptyQueue`          | No upcoming track remains   |
| `connection`          | A voice session connects    |
| `connectionDestroyed` | A voice session is disposed |

The queue advances tracks automatically. Don't call `queue.playNext()` inside a `playerFinish` listener.

## Player-level errors

The Player also emits errors and diagnostics not tied to a queue:

```ts
player.on('error', console.error);
player.on('debug', console.debug);
```

A skipped track is different from one that finished naturally. See the [event reference](/docs/reference/events) for argument order and other events.
