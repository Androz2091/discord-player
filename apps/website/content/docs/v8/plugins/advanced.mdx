---
title: Custom operations
description: Add your own typed operations and choose how they dispatch.
---

You can add operations to the registry. This is rarely needed. Source plugins normally use the built-in operations.

## Define an operation

Declare the operation's types, then register its policy on the Player:

```ts
import type { Operation } from 'discord-player';

declare module '@discord-player/plugin-host' {
  interface OperationMap {
    'track.audit': Operation<{ sourceId: string }, { accepted: boolean }, 'first'>;
  }
}

player.plugins.defineOperation('track.audit', 'first');
```

Plugins can then handle it, and you can run it:

```ts
ctx.on('track.audit', ({ sourceId }) => ({ accepted: sourceId.length > 0 }));

const result = await player.plugins.execute('track.audit', { sourceId: 'abc' });
```

Define the operation before any plugin registers a handler for it.

## Choose a policy

| Policy      | Use when                              |
| ----------- | ------------------------------------- |
| `first`     | One handler should answer             |
| `collect`   | You want an answer from every handler |
| `pipe`      | Handlers transform a value in turn    |
| `broadcast` | Handlers only need to be notified     |

## Keep data portable

Use JSON-compatible data for inputs and outputs if the result might be saved or sent to another process.

## Limits

Custom operations run inside the bot process. They are not sent to a remote Remedia server. A source that must work with a remote audio node should return a server-accessible URL from `track.stream`, or run on a [source host](/docs/v8/plugins/remote-hosts).
