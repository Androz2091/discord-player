title: Remote playback
description: Connect discord-player to remedia-server without installing FFmpeg on the bot host.

A remote node runs the **same Remedia engine** in a separate Rust service. Your bot still owns Discord Gateway events and source plugins; the server owns audio decoding, playback state, and voice output.

```ts
const player = new Player({
  nodes: [
    {
      id: 'audio-1',
      type: 'remote',
      url: 'remedias://audio.example.com',
      auth: {
        username: 'bot',
        password: process.env.REMEDIA_PASSWORD!,
      },
    },
  ],
  send: (guildId, packet) => sendGateway(guildId, packet),
});

await player.initialize(botUserId);
```

`remedia://` maps to WebSocket, `remedias://` to secure WebSocket. A missing endpoint path defaults to `/v1/ws`. Standard `ws://` and `wss://` URLs are also supported.

## Deploy the server

Install the [matching Remedia server release](https://github.com/twlite/remedia/releases/tag/v0.1.0-dev.4) on the audio host, not on the bot host. Use the official [server installation guide](https://github.com/twlite/remedia/blob/v0.1.0-dev.4/apps/docs/content/docs/server/installation.mdx). The standalone CLI supports:

```sh
remedia-server --generate-config-file
remedia-server doctor --config ./remedia.config.json --env-file .env
remedia-server serve --config ./remedia.config.json --env-file .env
remedia-server --list
```

The generated configuration denies playback URLs and file paths until you authorize sources. Set the referenced password in `.env`. The `--env-file` argument requires an existing file; `--optional-env-file` ignores a missing file. Neither loads values into the process-global environment.

The lightweight administrative CLI can run without FFmpeg. Native `serve` and `doctor` still require FFmpeg **9** shared libraries on the server. `--list` discovers running Remedia processes for the same local OS user and reports their health, resource counts, and listening ports; it is not a LAN scanner or process manager.

## Connection timing

Remedia `0.1.0-dev.3` uses a dedicated 80-second `voice.connect` client RPC timeout and allows 75 seconds on the server, independent of regular RPC timeout settings. The default overall join deadline is 100 seconds.

```ts
await queue.connect({ channelId, connectTimeoutMs: 120_000 });
```

Do not globally serialize guild joins to avoid timeouts. Each guild has an independent session. Read [voice recovery and concurrent joins](/docs/remedia/voice-recovery) before changing connection settings.

## Server setup details

Install compatible FFmpeg libraries **on the remote machine**. Start an authenticated `remedia-server` with its `remedia.config.json`; see the [server configuration reference](https://github.com/twlite/remedia/blob/v0.1.0-dev.4/apps/docs/content/docs/server/configuration.mdx) and [deployment guide](https://github.com/twlite/remedia/blob/main/apps/docs/content/docs/server/deployment.mdx).

For a public network, put TLS in front of the service, restrict source access, and protect credentials. Never expose your server with anonymous playback privileges.

## What can be streamed remotely?

Return a server-accessible URL or an allowed file path. A local Node.js `Readable`, private buffer, or local-only path cannot be transported through this source API. [Source plugins](/docs/plugins/streams) should resolve a URL the remote server can open.

## Recovery and affinity

Remedia assigns sessions to healthy nodes and keeps a guild sticky to its node. Remote connections attempt reconnect and session resumption. A missing or expired session is not equivalent to a clean, completed Track; observe diagnostics and recover deliberately.

Connected Remedia sessions have an explicit cross-node migration operation in the engine client, but a cutover may require reconnecting and reopening audio. Do not assume a gapless decoder transfer or automatic load shedding in discord-player.

## Crossfade capability negotiation

Use Remedia 0.1.0-dev.4 or newer with server crossfading enabled. The selected node must advertise `capabilities.crossfade.available`; the guild must also opt in at session creation. Unsupported nodes fall back to ordinary playback with a debug message. Existing sticky assignments are retained. See the [crossfade guide](/docs/guides/crossfade).
