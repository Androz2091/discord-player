# Security policy

Security vulnerabilities in discord-player should be reported privately to protect users and allow maintainers to investigate and address them before public disclosure.

## Reporting a vulnerability

**Do not disclose security vulnerabilities through public GitHub issues, pull requests, discussions, or other public channels.**

To report a vulnerability:

1. Open the repository's **Security** tab on GitHub.
2. Select **Report a vulnerability** to submit a private security advisory.
3. If private vulnerability reporting is unavailable, contact a repository maintainer through an available private communication channel.

Please include the following information where possible:

- **Affected versions:** The package version, commit, or revision where the vulnerability exists.
- **Description:** What the vulnerability is and its potential security impact.
- **Reproduction steps:** Clear instructions or a minimal proof of concept demonstrating the issue.
- **Supporting information:** Relevant logs, error messages, or other technical details.
- **Suggested mitigation:** Any known workarounds or potential fixes, if available.

Remove credentials, tokens, personal information, and other sensitive data from your report.

## Response and disclosure

Maintainers will review security reports and acknowledge them when possible. Confirmed vulnerabilities will be investigated and addressed based on their severity and impact.

When appropriate, maintainers will coordinate with the reporter to prepare a fix, publish a security advisory, and disclose the vulnerability responsibly.

**Please avoid publicly disclosing vulnerability details until a fix is available or a disclosure timeline has been agreed upon with the maintainers.**

Response and resolution times may vary depending on the complexity of the issue and maintainer availability.

Thank you for helping keep discord-player and its users secure.
